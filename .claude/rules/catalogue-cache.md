# カタログはメモリから読む

**作品・市期・タグはプロセスのメモリに全件載せ、公開 GET はそこから返す。**
ページのたびに Firestore のコレクションを走査してはいけない。

カタログは 155 作品と 200 期と 100 タグしかない。トップを開くとカルーセル・
一覧・タグが同時に走り、キャッシュが無いと **1 訪問で 350〜450 読み取り**
になっていた。155 件なら全部載せてソートする方が安い。

```
src/lib/ttlCache.ts          1 週間保持。同時ミスは 1 回にまとめる
src/lib/animeCatalogue.ts    versions/1/animes 全件
src/lib/seasonIndex.ts       seasons の collectionGroup 全件
src/lib/tagCatalogue.ts      versions/1/tags 全件
src/lib/readCaches.ts        管理画面から全部捨てる入口
```

## やること

- 一覧・statics・ids・作品 1 件・期一覧・タグは `animeCatalogue()` /
  `seasonIndex()` / `tagCatalogue()` から読む
- 書き込み（作品・期・評価・いいね）は、汚したキャッシュをすぐ
  `invalidate` する。書いたインスタンスは次の GET で作り直す
- カルーセルは全件 statics ではなく
  `GET /api/v1/animes/?sort=rating&cour=今季&limit=10`

## メモリに載せないもの

一覧に要らない、または件数が読めないものは毎回 Firestore でよい。

| 載せる | 載せない |
| --- | --- |
| 作品ドキュメント | 自分の評価・いいね（ユーザーごと） |
| 全市期 | コメント |
| タグ語彙 | ニュース |
| | `details/{locale}`（キャストなど長い項目） |

## 古さの割り切り

保持は **1 週間**。書いたインスタンスはすぐ捨てるが、別インスタンスは
最大 1 週間古いまま出せる。管理画面のキャッシュ削除か再起動で揃う。
155 件規模ならこの割り切りでよい。

HTTP の `Cache-Control`（ブラウザ・CDN 向けの数十秒〜数分）は別レイヤ。
メモリキャッシュの代わりにはしない。

## やってはいけない

- **公開 GET で `collection.get()` や `collectionGroup.get()` を新しく足す**
  — カタログにあるならメモリを見る
- **ユーザーごとの文書をカタログに混ぜる** — 人数分膨らみ、共有できない
- **invalidate せずに作品・評価・いいねを書く** — 一覧とヒーローが古いまま残る
- **TTL を短くして「新しさ」を稼ぐ** — 読み取りがまた訪問のたびに戻る。
  新しさが要るなら書いた側を捨てればよい
