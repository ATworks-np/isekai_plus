# 取得中はスケルトンを出す

**データを取得している間、そのデータを描くコンポーネントは必ずスケルトンを描く。**
空で描いてはいけない。スピナー1個で画面全体を置き換えてもいけない。

このサイトはほぼ全ての内容を取得後に描いている。取得中に何も描かないと、
画面が一度空になってから内容が飛び込んでくる。読み手には壊れて見えるし、
高さが確定しないので周りの要素がずれる。

## やること

- 取得中は、確定後と**同じ形・同じ高さ**のスケルトンを出す
- 件数が分かっているならその件数分、分からないなら実際に出る件数の目安で並べる
- MUI の `Skeleton` を使う（`variant="text" | "rectangular" | "circular"`）

```tsx
const { seasons, loading } = useSeasons(animeId)

if (loading) {
  return (
    <Stack spacing={1}>
      {Array.from({ length: 3 }, (_, i) => (
        <Skeleton key={i} variant="rectangular" height={72} />
      ))}
    </Stack>
  )
}
```

## やらないこと

- `if (loading) return null` — 一番やってはいけない。高さが消えて画面が飛ぶ
- `if (loading) return <CircularProgress />` で本体ごと差し替える。
  レイアウトが崩れるうえ、何が出てくるのか読み手に伝わらない
- スケルトンの高さを本体と変える。ずれるなら意味がない

## 例外

- **追加読み込み**（無限スクロールの2ページ目以降）は、すでに内容が見えていて
  高さも安定しているので、末尾のスピナーでよい
- **ボタンの中**（送信中など）はスピナーでよい。形が変わらないため
- **取得するものが無かった場合**はスケルトンではなく「まだありません」を出す。
  スケルトンは「これから来る」という意味なので、来ないものに使わない

## 判定

`useEffect` で `fetch` しているコンポーネント、または `loading` を返すフックを
使っているコンポーネントは、すべてこのルールの対象。
