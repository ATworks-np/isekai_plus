# 多言語データの持ち方

**短い項目は埋め込みマップ、長い項目は言語別サブコレクション。** どちらに
するかは「一覧で必要かどうか」で決まる。

```
versions/1/animes/{id}
  name  { ja, en? }            短い・一覧が20件まとめて読む → 埋め込み

  details/{locale}             長い・作品ページしか読まない → 言語別ドキュメント
    studios / staff / cast / themeSongs
    summary                    2〜3文の紹介。公式あらすじの転載ではない

  seasons/{seasonId}
    label                      スピンオフのみ。通常の期は order から生成する

  comments/{id}
    lang: 'ja'                 利用者の文。翻訳しない。書かれた言語を記録するだけ

versions/1/tags/{id}
  name      { ja, en? }
  criteria  日本語のみ           運用者向けの文なので翻訳対象外
```

## 埋め込みか、サブコレクションか

| | 埋め込みマップ | 言語別サブコレクション |
| --- | --- | --- |
| 例 | `name` | `details/ja` `details/en` |
| 長さ | 数十文字 | 数千文字 |
| 読む場面 | 一覧・詳細の両方 | 詳細だけ |
| 代償 | 全言語が毎回ついてくる | ドキュメントが1件増える |

一覧は作品を20件まとめて読む。ここでサブコレクションにすると**1ページで20回
追加読み取り**が発生する。逆に、50件規模のキャスト表を埋め込むと、日本語の
読者が英語のキャスト表まで毎回ダウンロードすることになる。

## 未翻訳は「キーを持たない」

```
name: { ja: "無職転生", en: "Mushoku Tensei" }   翻訳済み
name: { ja: "無職転生" }                        未翻訳
```

**空文字と日本語のコピーは書かない。** 書くと「翻訳済み」と区別できなくなり、
フォールバックの判断も、未翻訳一覧の作成もできなくなる。実際に作品155件のうち
100件がその状態で、掃除するまで何も判定できなかった。

書き込みAPIは、`ja` と同じ値の `en` を受け取っても保存しない。

## 生成できるものは保存しない

期のラベル（第1期・第2期）は `order` と `kind` から作る。保存すると、
212件の文字列を正しく書き、期を挿入したときに直し、言語が増えるたびに
212回翻訳することになる。実際の値は5種類しかなかった。

数え方は「season の中で何番目か」。スピンオフは番号を消費しない
（爆焔の次は第4期ではなく第3期）。

## やってはいけない

- **ロケール別のコレクション**（`animes_en`）— 作品が二重管理になる
- **短い項目の言語別ドキュメント** — 一覧の読み取りが件数分増える
- **利用者が書いた文の翻訳** — コメントは本人の言葉。`lang` を記録するだけ
- **UI文言をDBに置く** — 翻訳の差分がレビューできない。メッセージファイルに置く
